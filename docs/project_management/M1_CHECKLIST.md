# M1 — Validation MVP checklist

End state: **schema-driven deterministic validation** with **evidence** from real PDFs, **no chat/RAG/Airflow** in the core path, **no end-user configuration** of extractors.

## Product

- [x] `POST /api/validate-document` (multipart: `project_id`, `schema_id`, `schema_version`, `document` PDF)
- [x] `GET /api/projects/{id}/validation-schemas` (versioned schema listing)
- [x] Only **active** schema versions may validate (archived → **409**)
- [x] Response: `PASS` / `FAIL` / **`AMBIGUOUS`** + per-field rule + **evidence** (`text`, `block_id`, `page`, `bbox`, `section_label` when available) + optional **`ambiguous_fields`**
- [x] Frontend: project → schema/version pick → upload → result + PDF preview (in `ProjectValidationPage`)

## Pipeline (eight stages — implementation order)

1. [x] **Parse** — PyMuPDF → `TextBlock` + bbox + **`section_label`** (`infer_section_labels`)
2. [x] **Discovery** — ensemble extractors (regex + layout)
3. [x] **Schema mapping** — `map_candidates_to_schema` → `FieldEntry` per field (`found` / `missing` / `ambiguous`)
4. [x] **Gap-fill** — optional LLM hypotheses merged here when `VALIDATION_LLM_FALLBACK_ENABLED=true` (default **false**)
5. [x] **Inconsistency check** — `check_inconsistencies` → **`AMBIGUOUS`** status if any field is ambiguous
6. [x] **Resolution** — `resolve_from_field_map` (deterministic tie-break: source priority → confidence → **`b{n}` index**)
7. [x] **Validation engine** — `validate_schema`: **`required`**, **`range_validation`** (`min`/`max`), **`type_check`**
8. [x] **Result assembly** — `PipelineValidationResult` → API (`PASS` | `FAIL` | `AMBIGUOUS`)

## Schema DSL (fixture + persisted body)

- [x] Per-field **`required`**, **`min`** / **`max`** (not legacy `range` array)
- [x] Global **`rules`**: `required`, `range_validation`, `type_check`
