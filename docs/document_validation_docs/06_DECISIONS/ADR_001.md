# ADR 001 — RAG Removed from Core Pipeline

**Status**: Accepted
**Date**: 2026-Q1
**Deciders**: Core team

---

## Context

Early design discussions explored using a Retrieval-Augmented Generation (RAG) architecture for document validation. In this model, documents would be chunked and embedded into a vector database. Validation queries would retrieve relevant chunks and ask an LLM to determine compliance.

---

## Decision

**RAG is not used in the validation pipeline.** It is excluded from the core architecture entirely and will not be added in any milestone.

---

## Rationale

The core product requirement is **deterministic, auditable validation**. RAG introduces fundamental incompatibilities:

1. **Non-determinism**: Retrieval relevance rankings and LLM generations are probabilistic. The same document submitted twice may produce different validation results. This is unacceptable for compliance use cases.

2. **Opaque evidence**: RAG systems can fail silently. When a relevant chunk is not retrieved, the LLM may hallucinate a value or produce a generic response. The resulting answer has no traceable link to the source document.

3. **No field-level precision**: The system must produce evidence at the block level — citing the exact text snippet, page number, and bounding box where a value was found. RAG retrieval operates at the chunk level, which may span multiple blocks, fields, and even pages. This granularity is insufficient.

4. **Latency and cost**: RAG requires embedding the entire document at upload time and querying a vector index at validation time. This adds significant latency and infrastructure complexity for a use case that can be served deterministically by structured extraction.

5. **Complexity without benefit**: A regex + layout heuristics extractor can find labeled key-value pairs with 95%+ accuracy on structured and semi-structured documents. RAG does not improve accuracy for these document types; it only adds complexity.

---

## Consequences

- No vector database in the architecture (no Chroma, Pinecone, Weaviate, etc.)
- No document embedding at ingestion time
- No "semantic search" over document content
- LLM is used **only** as a controlled fallback in the gap-fill extraction pass, with temperature=0 and structured output
