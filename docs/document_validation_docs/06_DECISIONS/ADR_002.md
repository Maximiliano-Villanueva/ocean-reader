# ADR 002 — PDF Parsing: PyMuPDF as Primary, Docling as Future Option

**Status**: Accepted (PyMuPDF); Deferred (Docling evaluation)
**Date**: 2026-Q1
**Deciders**: Core team

---

## Context

The system needs to extract text blocks with bounding boxes from PDF files. Two mature options were evaluated:

- **PyMuPDF (fitz)**: Low-level PDF parsing library. Fast, mature, produces precise block geometry.
- **Docling (IBM Research)**: Higher-level document understanding library. Supports structure detection (tables, headings, figures), LLM-friendly output.

---

## Decision

**PyMuPDF is the primary PDF parser for Milestone 1.** Docling evaluation is deferred to a future milestone.

---

## Rationale for PyMuPDF

1. **Bounding box precision**: PyMuPDF's `page.get_text("dict")` provides block, line, and span-level bounding boxes with sub-pixel accuracy. The evidence model depends on precise bboxes for document highlighting.

2. **Determinism**: PyMuPDF is fully deterministic given the same PDF input. Same PDF → same blocks → same IDs. This is required for the reproducibility guarantee.

3. **Speed**: PyMuPDF is written in C and is very fast. It processes a typical 10-page PDF in < 100ms.

4. **Maturity**: PyMuPDF has been in production for over a decade with extensive test coverage. It handles malformed PDFs gracefully.

5. **Minimal dependency**: PyMuPDF has no network dependencies, no model downloads, and no GPU requirements. It works identically in development, CI, and production.

---

## Rationale for Deferring Docling

1. **Overkill for M1**: Milestone 1 validates semi-structured lab reports with consistent layouts. Table detection and semantic structure understanding are not needed at this stage.

2. **Non-determinism risk**: Docling uses ML models for structure detection. Model updates could change parsing behavior, breaking regression tests. This risk needs to be managed carefully.

3. **Larger footprint**: Docling installs transformer models (several hundred MB). This increases container size and cold-start time significantly.

4. **Evaluation deferred, not rejected**: Docling may provide significant value for unstructured or complex document types (M3+). When the repeating group extractor needs robust table detection, Docling should be re-evaluated.

---

## Future Evaluation Criteria for Docling

Docling should be re-evaluated if:

- The system needs to handle documents with complex tables that PyMuPDF cannot reliably parse
- Column-based extraction with `structure_hint: "table"` fails on real-world documents
- Document types require heading hierarchy detection beyond PyMuPDF's font-size heuristics

---

## Interface Design Consequence

The `parse_pdf_blocks` function and `TextBlock` type are designed to be parser-agnostic. The parser implementation can be swapped without changing the rest of the pipeline:

```python
# Current: PyMuPDF implementation
def parse_pdf_blocks(data: bytes) -> list[TextBlock]:
    import fitz  # lazy import — could be replaced with Docling adapter
    ...
```

If Docling is adopted, a `DoclingTextBlockAdapter` will translate Docling's output format into `list[TextBlock]` without changing any downstream code.
