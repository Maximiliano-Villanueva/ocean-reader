# ADR 004 — Hybrid schemas: strict DSL + open-ended LLM fields

**Status**: Accepted  
**Date**: 2026-05  
**Supersedes**: Partial relaxation of ADR 003 for schema authoring and open-ended runtime only.

---

## Context

Users need natural-language schema authoring and fields the deterministic engine cannot express (summaries, narrative checks, consolidated evaluations). Strict DSL (M1–M3) remains the core for auditable PASS/FAIL.

---

## Decision

1. **DSL version 3** adds top-level ``open_ended`` field map alongside strict ``fields``.
2. **Strict rules** are never evaluated by LLM. The rule engine and expression evaluator stay deterministic.
3. **Informative open-ended** fields (`informative_only: true`) do not change PASS/FAIL; they appear in reports only.
4. **Evaluated open-ended** fields use LLM with allowed tags: `pass`, `fail`, `ambiguous` — may promote run status (never replace strict engine errors).
5. **Schema authoring** uses a separate **Google ADK** service (`schema-agent`) backed by **Ollama** (`gemma4:e4b`). Human edits the draft JSON at any time; each chat request includes `CURRENT_SCHEMA_JSON`.
6. **Ollama** also powers optional validation LLM fallback, open-ended runtime, and vision extraction when enabled via env flags.
7. **Extraction** for open-ended uses `pdf_blocks` text (multimodal PDF→model deferred).
8. **Evidence**: `link_evidence: true` attaches bbox links from block quotes; false for free-form summaries.

---

## Consequences

- New env: `VALIDATION_OPEN_ENDED_ENABLED`, `OLLAMA_BASE_URL`, `LLM_MODEL` (`gemma4:e4b`), `SCHEMA_AGENT_URL`.
- Compose service `schema-agent` calls host Ollama via `host.docker.internal`.
- Wine corpus PDFs regenerated as rich multi-page documents; regression expectations unchanged with LLM disabled.
